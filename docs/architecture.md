# 架构

## 治理对象与执行关系

本 Skill 治理“写作目标被代理指标替代”：要求有思考却只增加感想，要求精练却持续删除，局部意见却触发全文同质加工。核心把决定依据固定在作品目的、当前位置的内容作用和实际变化上。

执行关系是：当前请求与材料形成工作目标，内容判断选择动作，角色方法实施动作，结果对照目标决定完成或修复。质量来自稿件实际效果；规则命中数、改动比例和过程表格不充当完成标准。

这条关系通过具体入口和资源所有权实现。根入口只路由；Guide 选择并实施写法；Audit 独立判断已确认的问题；共享契约和标准提供同一组语义依据。一个宿主 Agent 可以依次执行，普通任务无需多 Agent。

## 职责所有权

| 所有者 | 负责什么 | 使用者 |
| --- | --- | --- |
| `shared/core.md` | 任务目标、内容先行、取舍、授权、停止条件 | 所有入口及操作 |
| Guide `compose.md` | 从材料形成内容，再完成语言表达 | 创作与续写 |
| Guide `explain.md` | 解释中间层、术语、数据与篇幅深度的正面方法 | 解释、论述与信息展开 |
| Guide `registers.md` | 口头、正式、学术与个人声音的正面方法 | 语域与读者转换 |
| Guide `revise.md` | 原稿基线、编辑选择、替换应用、效果核对 | 编辑与重写 |
| Guide `transform.md` | 新用途决定保留与转换的内容 | 翻译、摘要与整理 |
| Audit `review.md` | 材料覆盖、语义判定、诊断与交接 | 审查与版本比较 |
| Audit `prohibitions.md` | 根因治理、表演性表达与内容缺口的禁止条件及裁决 | Audit |
| `shared/standards/` | 内容、组织、语言、推理、声音和来源的判定依据 | 两个角色按需使用 |
| `shared/protocols/context.md` | 读取、版本更新、恢复与工作状态 | 所有入口 |
| `shared/tooling/capabilities.md` | 宿主读取、定位编辑、差异和产物操作 | 使用工具的任务 |

共享层不依赖任何角色文件。Guide 的正面方法不以逐条排除 Audit 禁令作为创作流程；Audit 依据原稿与实际效果判定，无须装载 Guide 的全部执行方法。两者通过共同契约与领域标准协作。

## 操作之间传递什么

工作上下文只保留当前决定需要的信息，不创建固定表单或并行语义数据库。

| 工作位置 | 使用的材料 | 交给下一动作的内容 |
| --- | --- | --- |
| 路由 | 用户请求、现有上下文 | 成果、操作、材料位置、授权 |
| 创作选择 | 任务目的、材料和读者 | 选定内容、相互关系与表达方向 |
| 编辑选择 | 最新原稿、反馈、上下文 | 目标区域、实际改善、保留作用与必要依赖 |
| 应用修改 | 基线和已选定的编辑动作 | 替换内容及组成后的稿件 |
| 效果核对 | 请求、基线与实际变化 | 已完成结果，或仍需修复的具体问题 |
| 审核交接 | 确认问题和源稿 | 位置、实际影响、需恢复的关系、授权范围 |

这些是责任接口，短任务可在一次连续操作中完成。存在真正取舍时才比较候选做法，保留原文是编辑的合法结果。没有内容依据的变化返回材料判断，不进入全文生成。判断材料不足时处理具体缺口，不虚构理由。

## 创作与修订的不同执行语义

创作从所需内容开始。由材料形成判断、人物行动、情境或实用安排，再调用语言能力写成作品。内容充分且完成用途就收束。主动形成作品是 Guide 的责任，审核约束不把创作退化为安全而空泛的表态。

修订以最新指定稿为基线。局部任务先确定内容变化，只生成目标区域的替换句段，再由原稿和替换内容组成完整稿。未改区域直接沿用；阅读范围和交付全文均不改变权限。使用宿主已有定位编辑与差异能力，不开发另一套补丁系统。

实际依赖包括数量、指代、引用、前提、回扣和结构关系。因改变而失效的内容在授权内联动；没有失效的段落保持。明确锁定的范围不可越过，冲突需要说明。全篇重写允许重组，仍保留有效事实与明确约束。

应用后对照实际变化，检查是否解决目标以及仍有作用的内容是否保留。无关变化撤销，误删从基线恢复，已有效的修改继续保留。追加修订须有尚存的具体问题，不默认反复全篇审核。

## 审核的约束与回传

Audit 的禁止条件指向可定位的失败行为。语义成立就必须纠正；关键词命中、计数或用户标签只能触发阅读。审核也受防误判和只读约束。

对照版本时区分原问题、修复效果和新增损失。缺少原稿或修改请求时，判断止于已有材料支持的范围。报告给出需要修复的内容关系，不把“更自然、更深入”传给 Guide 作为新的全篇加工指标。

检查并修改沿同一授权交接，Guide 依据原稿选择正面的修复方法。修订后核对原问题及真实影响，完成即结束。独立审查停在诊断；普通局部写作不自动启动审核循环。

## 具体语言治理与正面能力的关系

直接禁令的**语义定义**由共享标准持有：`prose.md` 的 PROSE-09～PROSE-12 负责表演性口语、幽默金句、装饰性强调和虚构对立；`organization.md` 的 ORG-06 负责标题钩子。两个角色都读取其适用标准，避免 Guide 因缺少 Audit 文件而继续生成被禁止的内容，也避免在两个角色分别维护不同口径。

**Guide 的正面方法**分为原有构思、修订、转换，以及按内容触发的 `explain.md` 与 `registers.md`。前者从读者问题、术语、数据、前提和解释中间层形成具体内容；后者按口头、正式、学术、非虚构作者声音等场合选择可用表达方式。它们不提供装饰性幽默、金句或假互动的正面模板。

**Audit 的强制裁决**由 `prohibitions.md` 的 AUDIT-06 与 AUDIT-07 引用共享标准作出。前者对于确认为表演性行为的内容直接判定修复，后者针对说明浅薄、术语数据堆砌、语域错位等实际缺口核对内容关系。用词、标点或标题形式仅能辅助定位，无法独立确认违规。

共同决策契约持续防止新增规范退化为每段强制添加解释、每句去除某词、所有标题同长度等新代理指标。现有局部替换、原文保真和完成即停机制继续生效。

## 加载与依赖方向

启动共同基础只有 `core.md` 和 `context.md`。操作开始前读取角色方法；领域标准按内容关系选择。句段成文和语言审核加载 prose，纯构思、结构讨论、计数与版式操作不为语言规范先改写任务。

角色入口直接指向其 references，shared/INDEX 只导航共享能力。定位器从实际运行时 Markdown 收集定义，不维护第二套规则数据库。首次读完整文件；后续回查和恢复由上下文协议处理。

编号保留职责稳定的 CORE、WRITE、EDIT、XFORM、REVIEW 及领域前缀，AUDIT 由禁令文件独占。入口可达性、编号唯一性、未知引用与共享层反向依赖由打包检查覆盖。

## 分发

源码保存唯一的共享标准及两个角色的方法。协调安装包将角色转为 `roles/guide.md`、`roles/audit.md`，对应方法放在 `roles/guide/` 与 `roles/audit/`。独立包将本角色入口作为根 SKILL.md，自己的方法放在 references，只携带本角色与共享资源。

构建按实际文件映射重定位链接，在产物布局上检查引用和编号。源码与安装包中的定位器均从当前目录实际资源取定义。文档、评估材料和测试只进入源码包。

## 能力边界与验证

内容判断由宿主模型执行，文本保留与差异查看由宿主编辑工具执行。本仓库提供执行指引及可独立加载的资源，语义效果通过实际模型任务检验。

工具回归验证角色方法可达、共享层无反向依赖、独立包资源正确、编号定位和统计行为。行为评估另比较同一要求下的不同材料、多轮局部修订和语义误报；具体运行方式见[评估说明](../evals/README.md)。
