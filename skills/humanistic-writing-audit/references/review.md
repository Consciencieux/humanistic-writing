# 语义审核与版本比较

按照[决策契约](../../../shared/core.md)理解作品，以[治理禁令](prohibitions.md)裁决确认的问题。审核依据实际文字、请求和变化，不推测模型的内部动机。

<a id="review-01"></a>
## REVIEW-01 取得判定所需材料

确定检查范围、当前稿件和作品目的。全文任务覆盖全文，专项任务取得足够连续上下文。版本比较读取原稿、改稿及修改要求，用户确认的当前版本作为基准。

材料缺失时只判断能够支持的部分。例如只有改稿，可以指出解释缺失，但不能断言它曾被删除；没有修改请求，不能确定是否越权。具体缺口与受影响的判定一起说明。

<a id="review-02"></a>
## REVIEW-02 确认功能、变化和违反条件

先理解相关句段完成什么，再比较请求与实际结果。版本审查同时看原问题是否解决、既有作用是否保留、是否发生无关变化。静态词语或差异只帮助定位，继续回读上下文确定实际影响。

按适用禁令检查成立条件。发现“更客观”的改稿删除了有来源的个人经验，要指出丢失的归属或立场；发现保留了必要重复，则保留该表达。单个词语的出现不能确定作者、写作方式或违规。

<a id="review-03"></a>
## REVIEW-03 给出可修复的判断

确认的问题给出位置、必要原文、实际影响、适用禁令或标准，以及需要恢复或改变的内容关系。相同根因合并，修复范围保留真实依赖。审查输出可简短，不要求向用户展示内部加载和逐项核对表。

违反已经成立的禁令就明确要求修复；纯审美替代归为可选选择；材料缺口列为待核实。修复方向例如“保留第二段的原判断，恢复支持它的共享号码记录，撤销第一段无关改写”，不能用“全篇更有思考”代替定位。

<a id="review-04"></a>
## REVIEW-04 按权限结束或交接

只读任务交付诊断。明确要求检查并修改时，交接当前基线、确认问题、需保留的作用和授权范围，由 Guide 选择写法并实施修订。无需再次申请已有授权。

修订后的核对只处理原问题及实际变化；它们已解决就结束。未发现违规时允许通过，不为给出更多问题制造缺陷，不以找错数量或改动量评价审核成绩。
