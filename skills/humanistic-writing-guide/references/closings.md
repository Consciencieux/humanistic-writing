# 开篇、段落过渡与终止判断

起草或修订完整篇章的开头、段间推进与结尾时，配合[组织标准](../../../shared/standards/organization.md#org-03)与[推理标准](../../../shared/standards/reasoning.md#logic-05)使用。

<a id="closing-01"></a>
## CLOSING-01 切断“助手模式切换”，建立终止判断

模型在正文材料耗尽后，最容易从“作者完成作品”切换回“聊天助手服务对话”——想再回顾一遍、再拔高一层、或留个问题延续对话。

正文最后一条判断、最后一次行动或最后一个场景落地时，写作任务已经完成。判断要不要再写结尾，只核对一件事：**读者带着文章开头或主线那个核心需求进来，此刻是不是已经拿到明确落点？** 如果已经拿到，放弃继续生成的冲动；如果还悬在半空（只列完局部细节、未交代最终判断或去向），只补这最后一步，不把结尾当成总结表演。

<a id="closing-02"></a>
## CLOSING-02 针对四类尾段退化的直接拦截

发现最后一段出现以下任何一种冲动时，直接拦截并按对应动作处理：
* **想抛出新问题或反问**：文章结束就是结束，不邀请读者继续讨论。除非前文已经专门展开过、且当前材料确实解不开的卡点，否则末尾冒出的任何反问、伪开放追问或新议题一律删掉。
* **想用“综上所述 / 总而言之”重念前文**：前文已经讲清的关系和判断在结尾零复述。只有长文前面各节各自独立、尚未点明“合起来说明什么”时，才补一句推进层级的实质综合。
* **想拔高意义或喊积极口号**：不靠宏大前景、共同努力或虚假煽情给作品贴金。实用通知与书信只需保留真诚、简短的致歉或致谢，守住人情味即可。
* **话没落地就草草截断**：不以一句泛泛大实话草率收场，也不在最后一条局部数据后突然断电；把原本应由本文交代的结果、后续安排或人物反应写完再停。

<a id="closing-03"></a>
## CLOSING-03 结尾审查与修改的防误伤边界

执行[ORG-03](../../../shared/standards/organization.md#org-03)的结尾约束时，守住三项防误伤边界：
* 不因结尾出现问号，就把前文已铺垫的真实未决问题或叙事悬念机械判错。
* 不把长文或学术讨论必需的实质综合，误删成“禁止总结”。
* 不把实用通知与书信中真诚克制的致歉、感谢，误删成“多余废话”。

<a id="closing-04"></a>
## CLOSING-04 开篇切入与段间推进

开篇围绕读者当前的理解需要决定从哪里进入：读者已经熟悉背景时，直接进入核心事件、判断或矛盾；陌生读者缺少前提时，用简短篇幅交代必要基准，不铺陈“随着……的发展”等空泛大背景。

段与段之间靠内容的先后推进自然连接（比如从现象到原因、从具体材料到判断、或随时间与视角移动），不用“接下来我们再看”等过程播报硬切。发现两段之间发飘或跳跃时，先检查是不是段落顺序颠倒、中间少了一步交代，或者两段其实在重复同一件事。
