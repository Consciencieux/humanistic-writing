# 构思、起草与续写

创作从作品需要出发，形成可用内容，再进入句段表达。执行[决策契约](../../../shared/core.md)，以下方法用于实际选择。

<a id="write-01"></a>
## WRITE-01 找到值得写的内容

读取任务材料，确定读者要理解的关系、经历的变化、感受到的情境或完成的行动。已有思想链就继续展开；授权原创时主动选择角度、素材或情节。涉及多段构思或素材筛选时，按入口路由加载对应标准。

拟定主标题、小标题或目录时使用[标题方法](headings.md)，先确定内容重心再命名，成文后核对对应关系。

“有思考”落实为值得表达的判断，“自然”落实为适合对象与场合的表达，“深入”落实为当前尚需展开的关系。这些选择应在材料中有落点。没有原稿时直接形成内容，不把等待用户提供所有观点作为默认做法。

<a id="write-02"></a>
## WRITE-02 发展所选内容与关系

判断需要理由就展开理由；行动引起人物变化就写清相关行动与反应；实用文字围绕读者要做的事组织。决定哪些材料参与表达、如何连接，以及在哪个位置主要展开。需要复杂解释或特定语域时，由入口路由补充[解释方法](explain.md)或[语域方法](registers.md)及相应共享标准。

例如材料是“自由发言后讨论时间增加，发言人数未变，两人反映找不到加入机会”。值得展开的是时长与参与机会的区别，以及反馈怎样支持改进方向。分析完成后直接表达该判断。若另一份材料已把这个区别和理由讲清，保留它，继续处理剩余内容。

讨论和分析任务先确定实际问题，按推理标准形成或发展判断；若需查资料，选择能区分解释的证据。遇到新证据推翻初始设想时调整内容，不在原结论上补丁式附加例外。

文学创作可通过情境、行动、意象和节奏形成意义。给每段配齐事实、解释与总结会破坏这种安排；按当前作品需要选择发展方式。

<a id="write-03"></a>
## WRITE-03 把意思写成当前作品的语言

内容及其关系明确后，读取[语言标准](../../../shared/standards/prose.md)按读者理解顺序连续成文；仅当作品需要完整开篇、段落过渡或收束时，按需加载[开篇与收束方法](closings.md)。选择句法、详略、停顿与修辞，使需要的意思、声音和体验能够发生。不同作用的段落可以采用不同表达。

续写读取连接位置和必要前文，沿用已成立的事实、视角与关系，从尚未完成的内容继续。写作中发现材料无法支撑原安排，就调整内容选择，不用过渡和总结填补空位。

<a id="write-04"></a>
## WRITE-04 读回作品并完成

按原任务读回本次单元，按实际内容核对以下问题，短任务可一次读回完成：
1. **开头与结尾检查**：开篇第一句和结尾最后一句是否承担了实际功能（必要背景、作者归属、语气节奏、收束落点或叙事余韵）？仅在确认属于无作用空转、莫名反问或同义总结时删改（若涉及收束重构，按[开篇与收束方法](closings.md)处理）。
2. **中间层检查**：是否出现“只贴了结论和数字，却未写清前者如何推出后者”的段落断层？
3. **判断与表达检查**：是否有虚构前提、遗漏的可成立判断、强度失真、无关防御、助手套语或机械复述？依据适用的推理与语言禁令修复；真实限制和有效修辞保留。
4. **约束检查**：明确的事实、格式、授权范围和篇幅条件是否满足？发现具体缺口就修复；内容已完成其作用时收束。

交付作品本身。内部选材、加载和判断过程留在工作上下文；用户没有要求时，不附逐项自评或另一版全文。需要编辑已有部分时转入[修订方法](revise.md)，保持其基线与授权。
