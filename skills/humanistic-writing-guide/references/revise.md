# 基于原稿的修订

原稿是本轮的工作基线。执行[决策契约](../../../shared/core.md)，先确定具体变化，再将变化应用到原稿。普通任务不另建编辑计划文件。

<a id="edit-01"></a>
## EDIT-01 取得可编辑的基线

读取最新指定稿、本轮反馈和足以判断的上下文。确定用户要改善的内容或体验、允许改变的层次，以及已经成立的内容和表达选择。作者后续确认的稿件优先于 Agent 的旧稿。

将阅读、修改和交付范围分开：阅读全文可只改一段；返回全文时未改部分取自原稿。明确的全篇重写可以重新组织，事实、作者立场和其他仍有效要求继续约束结果。

<a id="edit-02"></a>
## EDIT-02 形成具体的编辑决定

在反馈指向的位置，理解已有内容怎样起作用，辨认实际缺口或用户选定的新效果。先确定要保留、补足、移动或改变的内容，再选择编辑动作。能够直接完成的小修改直接做；有实质取舍时比较合适做法，包括保留原文。

“段落太长”可能需要合并重复、收紧句子或拆开必要层次，依据[组织标准](../../../shared/standards/organization.md#org-05)选择。“缺少思考”可能需要补理由、明确已有判断或继续发展问题，依据[内容](../../../shared/standards/content.md)和[推理](../../../shared/standards/reasoning.md)处理。已充分的分析保留。纯审美转换按用户明确偏好执行，无须虚构缺陷。

例如，预约说明中已有校验步骤、共享号码的例外和服务台处理办法，拥挤主要来自层次安排，就拆分关系并收紧措辞。会议通知把同一时间地点讲了四遍，就合并重复。两处同样要求“缩短一些”，保留的信息作用决定各自的删改量。

决定要落到当前内容及预期改善。“看起来改得更多”“更短”“更像有思考”不能单独支持动作。没有具体改善依据时回到原文判断，不先对全文执行同一种加工。

<a id="edit-03"></a>
## EDIT-03 生成替换内容并应用

按所选动作读取适用的语言与专项标准，生成目标区域的替换内容。局部修订使用宿主的定位编辑；纯文本完整稿由未改原文与替换内容组合。文件定位、保存和差异操作采用[工具方法](../../../shared/tooling/capabilities.md#tool-04)。不要凭记忆重写整份稿件再声称只改了一段。

必要联动沿内容依赖处理：删去第二轮访谈，相关“两轮”和后续条件随之修正；仍有效的公开计划保留。仅因语气可更统一而改其他段落，不构成依赖修复。用户明确锁定的范围外内容不得改动；依赖越过该边界时说明具体冲突并完成可独立处理的部分。

整体重构按授权重排与重写，不为维持小 diff 保留失效结构。执行期间用户更新原稿时，先重新取得最新基线，保留其改动后再应用本轮变化。

<a id="edit-04"></a>
## EDIT-04 对照实际变化判断收益与损失

读回替换处及受影响的关系，必要时查看原稿与成品的差异。确认本轮问题得到处理，留下的事实、前提、理由、情节、关键细节和声音仍能完成原有作用。只剩结论、但读者已无法理解它怎样成立时，恢复必要支撑。

发现无关变化就撤销；发现误删就从基线恢复对应内容，保留已经有效的修改。缩减明确字数预算时，按目标读者取舍次要展开；摘要与用途转换用[转换方法](transform.md)，普通润色沿用原任务的内容责任。

差异定位变化，语义判断决定变化是否合理。检查对象是原问题和真实影响，不因一次局部修复再开展全文风格加工。

<a id="edit-05"></a>
## EDIT-05 结束本轮并保留连续性

本轮目标已实现，必要作用保留，依赖与明确约束正确时交付。继续修改应解决剩余具体问题；没有这样的缺口就保留当前结果。输出局部还是全文按请求决定。

后续反馈在最新稿上更新相关选择。此前接受的分析、事实与声音继续有效，除非用户改变它们或新材料要求修正。恢复被过度压缩的内容时读取对应原稿，不靠新套话补字数。跨会话按[上下文协议](../../../shared/protocols/context.md#ctx-04)保留版本与未完成事项。
