# 解释、分析与信息展开

当任务需要说明概念、形成观点、解释数据、解决“空洞但很长”或“专业但难懂”的问题时读取。先根据[内容标准](../../../shared/standards/content.md)与[推理标准](../../../shared/standards/reasoning.md)确定关系，再写给当前读者。

<a id="explain-01"></a>
## EXPLAIN-01 从读者尚不理解的关系展开

找到要解释的对象、读者已有的理解与需要到达的判断。查明中间缺少的是真实原因、作用过程、判断依据、条件还是具体后果。选择最能解决该缺口的材料，把关键前提放在它实际支持的命题附近。

例如，材料只有“有三项推广理由和两项争议”，就从每项理由与决策的关系中选择真正需要解释的部分。列出名称只完成目录；原因、涉及的主体及其影响若确为本段要回答的问题，就应展开这些关系。不要为了形式完整，让每项都占同样篇幅。

<a id="explain-02"></a>
## EXPLAIN-02 处理术语时保留准确含义

确定术语在当前推理中指称什么；专业读者已有共同定义时直接使用，非专业听众需要时说明它测量什么、为什么与当前判断相关。定义和解释以读者将要使用的内容为界。术语没有参与判断、数据或必要叙述时可以删去；关键术语不能因追求通俗而用含混的日常词替代。

例如，向跨专业听众讲某项排放研究，先说明所讨论的排放物及测试条件，再选择与当前结论直接相关的指标。专业测量名称若是理解比较的前提，应在它第一次承担解释任务时交代含义；不必沿着实验报告把全部指标逐项读给听众。

<a id="explain-03"></a>
## EXPLAIN-03 用数据建立具体判断

先确定需要展示的观察或比较，再选择数据。核对单位、分母、测量范围和比较条件，使读者知道数字回答什么问题；数字无法支持的结论不能靠语气加重来补足。需要估算实际后果时写出计算依据与假设，缺少输入就说明缺口，不能让“读者自己心里有数”替代必要解释。

示例材料：三个社区延长开放后，夜间使用人数上升，但没有记录同期对照数据。合理陈述是：在这三个社区观察到了增长；若要判断增长有多少由开放时间引起，还需与同期其他变化区分。这里的限定紧贴因果问题，不要把它变成针对无关主张的免责声明。

<a id="explain-04"></a>
## EXPLAIN-04 处理篇幅与论证密度

较长的段落如果缺少中间解释，应补必要的论证关系，而非简单删除或追加总结。如果已有关系充分但阅读拥挤，就调整句子与段落的组织。判断需要几个例子、解释到什么深度，取决于读者理解所需的层次以及材料是否支持。

原稿表达有效的判断、例子和节奏要保留；一项问题修好就结束。禁止将“每段都要完整展开”转成每段固定包含定义、数据、举例和总结的配方。具体编辑执行采用[修订方法](revise.md)。
