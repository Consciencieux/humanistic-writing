# 加载、基线与接续

本协议管理资源和工作状态。写作判断由[决策契约](../core.md)负责，具体操作由当前角色方法负责。

<a id="ctx-01"></a>
## CTX-01 从当前操作开始

每次进入协调、Guide 或 Audit，完整读取当前入口、决策契约和本协议。随后按入口读取当前操作的方法，再依据实际内容选择专项标准。进入句段成文或语言审查时读取[语言标准](../standards/prose.md)；纯构思、结构讨论或格式操作按其任务取用资源。

[能力索引](../INDEX.md)只用于导航，已知路径时直接读对应文件。同次交接可复用完整、未变且仍在有效上下文中的原文。引用一个文件不表示需要递归读取其全部链接，未进入的操作不提前加载。

<a id="ctx-02"></a>
## CTX-02 完整读取适用资源

首次使用选中的方法或标准，读取全文及其中的适用条件、示例和区别；工具截断就接续到末尾。已完整读取后的定向回查，可以只取相关完整小节。编号和锚点用于定位，也可用[定位器](../../scripts/rules.py)取得文件与行号。

正文阅读范围由任务决定：判断一段要有足够上下文，全文审查须覆盖全文。路径、摘要和“已读”记录用于恢复，不能替代判断所需的实际文字。

<a id="ctx-03"></a>
## CTX-03 在改变影响判断时刷新

用户更新稿件后重新取得当前基线及受影响上下文；规则或来源改变后重读改变的文件并修正相关决定。切换角色或操作时补读该角色和方法，保留仍适用的作品目标与授权。

长篇检索或工具操作后返回写作，先回到当前稿、所选内容和未完成目标，再补回已退出上下文的必要规则。新会话或压缩后按入口恢复，缺原文就读取原文，不按固定分钟数或段落数全量刷新。

<a id="ctx-04"></a>
## CTX-04 保存最小工作状态

短任务沿用当前上下文。跨会话、多文件或协作任务使用[状态片段](../../assets/writing-state.md)：Objective 保存成果与授权；Decisions 保存仍有效的内容选择及当前稿位置；Current Work 保存具体未完成问题、受影响范围与下一动作。

当前文稿维护正文，原始材料维护事实。状态只保存定位和接续必需的选择，不建立与正文并行的内容数据库。交接审核意见时携带其位置、实际影响和需要保留的关系。

新反馈只更新相关决定；真正改变目标或推翻旧依据时同步更新。误删恢复要取得被删内容所在的原稿。完成后结束，不留逐段证明、逐轮日志或无条件审批记录。
