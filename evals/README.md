# 行为评估

[cases.json](cases.json)包含合成任务及评审判据。材料用于检验内容决策、编辑保真和审核能力，不作为用户经历或既有文章的事实记录。

## 通过真实入口运行

选定同一宿主与模型，分别安装待比较版本。每个案例只向执行模型提供 `task`、必要的 `fixtures` 或依次发送 `turns`，并激活 `entry` 对应的入口。不得提前注入 `rules`、`expect`、`avoid`、分组名称或预选的专项加载清单。

执行模型须通过入口自行决定操作与读取资源。评审读取实际产物、必要的工具调用以及案例判据；过程中的自我声明不能代替稿件。只请求正文时，模型不需要输出决策表或思考记录。

文件任务将 fixture 复制到临时工作区，用户只授权修改副本。多轮任务下一轮继续使用上一轮实际输出；用户提供新的指定稿时才替换基线。记录宿主、模型、版本、输入与实际输出；需要检查稳定性时使用相同条件重复，结果保存在 evals/runs/。

## 架构级情境

| 情境 | 案例 | 观察重点 |
| --- | --- | --- |
| 同样要求缩短，材料承担不同作用 | CASE-18、CASE-19 | 必要层次整理与重复删除产生不同动作，未指定比例不成为目标 |
| 同样要求有思考，一份已有分析、一份缺少推理 | CASE-27、CASE-28 | 保留成立判断与真正发展内容，不批量插入第一人称 |
| 授权范围与实际依赖 | CASE-13、CASE-17、CASE-21、CASE-31 | 局部精确保留，必要联动完成，全文重构授权得到使用 |
| 多轮反馈与误删恢复 | CASE-23、CASE-24、CASE-32 | 以最新稿继续，保留已经接受的分析与声音 |
| 形式相似但语义不同 | CASE-29、CASE-30 | 有作用的句式保留，无典型词语的空泛内容仍能被识别 |
| 明确偏好和精确约束 | CASE-10、CASE-14、CASE-25、CASE-33 | 执行真实授权，不把可衡量要求误报为代理替代 |
| 达成后停止、未完成时继续 | CASE-22、CASE-34 | 不继续破坏已完成内容，也不以少改为由留下实际缺口 |

## 如何判断

将目标是否达成、有效作用是否保留、无关内容是否稳定分别核对。必要依据应检查其支持关系；保留几个关键词不能替代保留意义。允许多种正确写法，不采用风格评分、统一压缩比例或固定标准答案。

局部修改中明确保持不变的区域，可以对照源稿做精确文本比较。文件任务检查实际成品的变化，其他文本文件需保持原样。段内语义与创作效果由阅读判断。审核区分确认违规、可选偏好与材料缺口，也检查误报和只读权限。

未运行模型的案例不填写通过结论。源码工具测试负责资源、编号与封装；行为案例在维护时定向运行，不加入每次日常写作流程。
